A contract test checks the exact request or response shape at an application boundary. A mobile-to-site integration test is stronger: it creates the request with the mobile HTTP client and sends it to a running site backend. A MockEngine test is not an integration test because it replaces the server with a fake response. A test case is a source test method or class. A test filter is the exact Gradle `--tests` argument that selects that test case or class. A live run is backend-backed execution of a test case after the local readiness gate succeeds; a class-filter run or a local Compose test is not a live run.

The Tournament class `MobileTournamentEventEditorApiContractTest` uses the real mobile `MvpApiClient` -> `POST /api/events/editor` path through `MobileApiTestSession`. Its current live XML result reports two passing tests: unscheduled `CREATE_ONLY` create/reload and scheduled `PROPOSED` acceptance with placements and reload. The existing One-Time Event test case and its test filter remain the required generic field-compatibility path.

The Event Editor create command has contract version `3`. The site schema requires this shape:

    {
      "contractVersion": 3,
      "createOperationId": "...",
      "expectedRevisions": {
        "editorRevision": "...",
        "staffRevision": null,
        "scheduleRevision": "..."
      },
      "draft": { ... },
      "completion": { "mode": "CREATE_ONLY" }
    }

The field must remain required because the server uses it to prevent stale create operations. The mobile client must send the values from the create bootstrap snapshot.
