# Establish BracketIQ web tokens and Base UI primitives

This ExecPlan is a living document. Keep the `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` sections current while work proceeds.

Maintain this document in accordance with `PLANS.md` at the repository root. A contributor must be able to restart the work from this file and the current working tree only.

## Purpose / Big Picture

BracketIQ needs one owned visual foundation before product Surfaces can move away from Mantine. After this work, contributors can build a new web Surface with BracketIQ color and spacing tokens, Roboto Flex, standard Tailwind 4 breakpoints, accessible Base UI primitives, and one Sonner notification API. They do not need to introduce another component system.

The visible proof is a light-theme primitive set that works with a mouse and keyboard at desktop and mobile widths. Dialogs restore focus. Menus, selects, comboboxes, tabs, sliders, and calendars work from the keyboard. Form controls have programmatic labels. Notifications appear through the application notification module. Focus remains visible, motion respects the reduced-motion setting, controls work at 200% zoom, and touch targets are at least 44 by 44 CSS pixels.

This issue adds the foundation only. It does not migrate a product Surface, rewrite a product form, change React Hook Form state or validation, remove Mantine, remove Radix packages that current code still uses, or claim that the Mantine migration is complete. Existing Mantine providers, styles, tests, and product callers stay in place until later area issues migrate them.

  Evidence: files include `EventCard.tsx`, `PaymentModal.tsx`, and `TeamCard.tsx`; no `button.tsx`, `dialog.tsx`, or other lowercase primitive files exist at the planning base.
